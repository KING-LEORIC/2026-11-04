## 2. 변환과 관찰

### 2-1. 각 전처리 단계가 바꾸는 정보

| 단계 | 처리 방법 | 바뀌는 정보와 목적 |
|---|---|---|
| Gray | `cv2.cvtColor(image, cv2.COLOR_BGR2GRAY)` | BGR 3채널의 색상 정보를 밝기 중심의 1채널로 변환한다. 색상 차이는 사라지지만 명암과 형태 정보는 남는다. |
| Resize | `cv2.resize(gray, (160, 120))` | 이미지의 너비와 높이를 각각 줄인다. 처리할 픽셀 수와 연산량이 감소하지만 세부 정보도 줄어들 수 있다. |
| Gaussian Blur | `cv2.GaussianBlur(small, (3, 3), 0)` | 주변 픽셀을 가중 평균하여 작은 변화와 노이즈를 완화한다. 동시에 일부 경계와 세부 묘사도 흐려질 수 있다. |
| Threshold | `cv2.threshold(blur, 127, 255, cv2.THRESH_BINARY)` | 픽셀 밝기를 기준으로 0 또는 255로 나눈다. 연속적인 명암 정보가 사라지고 이진 형태가 남는다. |
| Morphology | `cv2.morphologyEx(binary, cv2.MORPH_OPEN, kernel)` | 침식 후 팽창을 수행한다. 구조 요소보다 작은 흰색 노이즈를 제거하는 데 도움이 되지만 작은 객체나 가는 부분도 손상될 수 있다. |
| Canny Edge | `cv2.Canny(blur, 80, 160)` | 밝기가 급격하게 변하는 경계를 검출한다. 객체 내부의 색상이나 면적 정보보다는 윤곽선 정보가 강조된다. |
| Augmentation | 좌우 반전 후 밝기 15 증가 | 이미지 방향과 밝기를 바꿔 학습 데이터의 다양성을 높인다. 이 실습에서는 원본을 직접 덮어쓰지 않고 별도 결과를 만든다. |

### 2-2. 원본과 처리 결과 비교에서 확인한 변화

**관찰 1: 색상 정보가 제거되고 명암 정보가 남았다.**

`scene.png`와 `objects.png`의 비교 이미지에서 원본의 빨강·초록·파랑 영역은 Gray 처리 후 서로 다른 밝기의 회색 영역으로 바뀌었다. 따라서 색상 자체는 구분할 수 없지만 밝기 차이와 도형의 위치 및 형태는 확인할 수 있었다.

**관찰 2: 면적을 가진 객체가 윤곽선 중심으로 표현되었다.**

Canny 결과에서는 원과 사각형, 직선의 경계가 주로 흰색 선으로 나타나고 내부 영역은 대부분 검은색으로 표현되었다. 이로써 Edge 검출은 객체의 채워진 면적이나 색상보다 경계의 위치를 강조한다는 점을 확인했다.

추가로 `noisy.png`의 비교 이미지에서는 작은 점 형태의 변화가 관찰되었다. 작은 잡음이나 불규칙한 밝기 변화도 Edge 검출 결과에 영향을 줄 수 있으므로, Blur와 Morphology 등의 전처리 설정이 중요하다.

## 3. 검증 증거

### 3-1. 이미지 파일과 데이터 검증

이미지 3개에 대해 각각 7개 단계의 결과를 저장했다.

- 이미지 처리 단계: Gray, Small, Blur, Binary, Opened, Edge, Aug
- 처리 결과 이미지: 3개 × 7개 = 21개 PNG
- 비교 이미지: 원본·Gray·Edge를 연결한 이미지 3개
- PNG 결과 파일 합계: 24개

`result_summary.csv`에는 각 결과 이미지의 파일 경로, 높이, 너비, 채널 수, 자료형 및 저장 전후 일치 여부를 기록했다.

검증 프로그램의 실제 출력:

```python
{
    'image_rows': 21,
    'images_ok': True,
    'source_unchanged': True,
    'video_ok': True
}
```

- `image_rows = 21`: CSV에 기록된 이미지 처리 결과가 21개다.
- `images_ok = True`: 이미지 파일을 다시 읽을 수 있고, 실제 shape·dtype·채널 수가 CSV 기록과 일치하며, PNG 저장 전후 배열도 일치했다.
- `source_unchanged = True`: 실행 전에 기록한 원본 이미지와 영상의 SHA-256 해시값이 실행 후에도 일치했다.
- `video_ok = True`: 영상 Frame 수, FPS, 크기 및 채널 검증을 통과했다.

이미지 결과의 크기는 단계에 따라 다르다.

| 처리 결과 | 크기(너비 × 높이) | 채널 |
|---|---:|---:|
| Gray | 320 × 240 | 1 |
| Small | 160 × 120 | 1 |
| Blur | 160 × 120 | 1 |
| Binary | 160 × 120 | 1 |
| Opened | 160 × 120 | 1 |
| Edge | 160 × 120 | 1 |
| Aug | 160 × 120 | 3 |

모든 처리 결과는 `uint8` 자료형으로 저장되었다.

### 3-2. 영상 read/write 검증

`video_report.json`의 실제 결과:

| 항목 | 결과 |
|---|---:|
| 입력·출력 객체 열기 | 성공 (`opened: true`) |
| 기록한 Frame | 48 |
| 다시 읽은 Frame | 48 |
| FPS | 12.0 |
| 너비 | 160 |
| 높이 | 120 |
| 출력 채널 | 3 (BGR) |
| 처리 소요 시간 | 약 0.0355초 |

재생시간 계산:

\[
\text{재생시간} = \frac{48\ \text{Frame}}{12\ \text{Frame/초}} = 4\ \text{초}
\]

따라서 영상은 48개 Frame을 기록했고, 저장된 영상에서도 48개 Frame을 다시 읽었다. FPS는 12.0이며, 영상 크기는 160×120이고 각 Frame은 3채널 BGR이다.

### 3-3. PNG 재읽기와 손실 코덱의 차이

**PNG**

PNG는 무손실 압축 형식이다. 이번 실습에서는 `cv2.imwrite()`로 저장한 PNG를 `cv2.imread(..., cv2.IMREAD_UNCHANGED)`로 다시 읽고 `np.array_equal()`로 저장 전후 배열을 비교했다. 검증 결과 모든 이미지의 저장 전후 배열이 일치했다.

**MJPG 영상**

영상은 `VideoWriter_fourcc(*"MJPG")`를 사용해 AVI 파일로 저장했다. MJPG는 각 Frame을 JPEG 방식으로 압축하는 손실 압축 방식이다. 따라서 저장 전후 픽셀값이 완전히 같다고 보장할 수 없다.

이번 검증에서는 영상의 기록·재읽기 Frame 수, FPS, 크기를 확인했지만 원본 Frame과 재생성 Frame의 픽셀 단위 동일성이나 화질 손실 정도를 측정하지는 않았다.

## 4. 한계와 다음 단계

### 4-1. Edge 픽셀 수를 품질 점수로 단정할 수 없는 이유

Edge 픽셀 수가 많다고 이미지 품질이나 객체 검출 성능이 반드시 좋은 것은 아니다.

- 객체의 경계가 선명하면 Edge가 증가할 수 있다.
- 노이즈가 많아도 불필요한 Edge가 증가할 수 있다.
- 임계값 설정에 따라 검출되는 Edge의 수가 달라진다.
- 중요한 객체의 경계가 누락되어도 다른 작은 경계가 많으면 전체 Edge 수는 높게 나올 수 있다.

따라서 Edge 픽셀 수는 특정 처리 결과의 특징을 나타내는 참고 지표일 뿐, 단독으로 품질을 평가하는 점수로 사용할 수 없다. 실제 성능을 평가하려면 목적에 맞는 정답 데이터와 Precision, Recall, F1 등의 평가 지표가 필요하다.

### 4-2. 증강이 라벨 의미를 바꿀 수 있는 사례

좌우 반전이나 회전, 밝기 변경은 모든 이미지에 무조건 적용할 수 있는 것은 아니다.

- 숫자 `6`과 `9`처럼 방향에 따라 의미가 달라지는 이미지
- 좌우 방향이 중요한 교통 표지판이나 화살표
- 좌우 반전으로 운전석 위치나 도로 진행 방향이 바뀌는 차량 이미지
- 밝기 변화로 신호등이나 색상에 의존하는 분류 라벨이 달라질 수 있는 이미지

이번 실습의 좌우 반전 및 밝기 증가도 데이터의 의미를 보존하는지 확인한 후 사용해야 한다. 증강 후에도 정답 라벨이 동일하게 유지되는지 검토해야 한다.

### 4-3. 모델 입력으로 사용하기 전에 다시 확인할 항목

1. **이미지 크기:** 모델이 요구하는 입력 너비와 높이에 맞는지 확인한다.
2. **채널 수와 색상 순서:** 모델이 Grayscale 1채널을 요구하는지, RGB 3채널을 요구하는지 확인한다. OpenCV는 기본적으로 BGR 순서이므로 RGB 변환이 필요한지 확인한다.
3. **자료형과 정규화:** `uint8` 픽셀값을 모델이 요구하는 `float32` 등으로 변환하고, 필요하다면 0~1 또는 -1~1 범위로 정규화한다.
4. **전처리 일관성:** 학습·검증·실제 추론 단계에서 동일한 전처리 규칙을 적용한다.
5. **데이터 누수:** 학습 데이터와 검증 데이터가 중복되거나 증강된 동일 원본이 서로 다른 데이터 집합에 섞이지 않도록 한다.
6. **라벨 보존:** 증강 후에도 이미지의 정답 라벨이 유효한지 확인한다.
7. **학습 데이터 적합성:** Resize, Blur, Threshold, Morphology, Edge 처리가 모델이 학습해야 할 중요한 정보를 지나치게 제거하지 않는지 확인한다.

## 5. 종합 결론

이번 실습에서는 3개의 원본 이미지를 대상으로 Gray, Resize, Gaussian Blur, Threshold, Morphology, Canny Edge 및 Augmentation 처리를 수행했다. 총 21개의 단계별 이미지 결과와 3개의 비교 이미지를 저장했다.

영상은 48개 Frame을 12 FPS로 처리해 160×120 크기의 AVI 파일로 저장했다. 재읽기 결과에서도 48개 Frame이 확인되었으며, 재생시간은 4초로 계산되었다.

최종 검증 결과 이미지 처리 행 수, 이미지 저장 및 재읽기, 원본 파일 보존, 영상 처리 검증 항목이 모두 통과했다.

이번 실습을 통해 이미지 전처리는 단순히 이미지를 변환하는 과정이 아니라, 색상·명암·공간 해상도·노이즈·객체 경계 중 어떤 정보를 유지하고 어떤 정보를 줄일지 결정하는 과정이라는 점을 확인했다. 이후 모델 학습에 적용할 때는 모델의 입력 형식과 실제 분류·검출 목적에 맞춰 전처리 및 증강 방법을 선택해야 한다.
